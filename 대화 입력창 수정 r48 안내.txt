r48 · 키즈룸·싱어·세션의 대화 입력창 유지

가장 중요한 수정
- 참여자 대화 기록 바로 아래에 ‘음향석에 메시지 보내기’ 입력창을 추가했습니다.
  답변 수신, 조치 완료, 확인 완료, 요청 취소, 음향석 보관 후에도 유지됩니다.
- 참여자의 대화는 접히는 창이 아닌 고정된 대화 영역으로 표시합니다.
- 새 메시지를 보내면 음향석의 보관 상태가 풀리고 진행 대화에 다시 나타납니다.
  기존 요청을 임의로 다시 미완료 처리하지 않고, 별도의 대화 메시지로 보관합니다.
- 음향석에서도 보관함에서 바로 답변할 수 있습니다. 답변하면 진행 대화로 이동합니다.
- 음향석도 접히는 창 대신 고정 대화 영역을 사용해 입력창이 갑자기 접히는 일을 방지합니다.
- 메시지를 작성하는 동안 상대방의 답변이 도착해도 메시지를 보낼 수 있습니다.
  완료·보관 같은 상태 변경은 기존의 동시 변경 검사를 그대로 유지합니다.
- 새 참여자 메시지는 무음 팝업과 ‘새 메시지’ 표시로 알립니다.
  새 요청이 없어도 메시지 확인·처리 완료가 가능합니다.
- 메시지와 답변이 같은 시각에 저장되더라도 실제 저장 순서를 유지합니다.
  이미 답변한 메시지가 새 메시지로 잘못 남는 현상을 방지합니다.
- 연결 오류로 전송 결과가 불명확하면 내용과 ‘이 메시지 다시 보내기’를 유지합니다.
  재시도는 같은 메시지 ID를 사용하며 이미 저장됐어도 중복 추가하지 않습니다.
- 참여자는 본인 대화에만 메시지를 쓸 수 있습니다. 공개 큐시트에 대화가 표시되지 않습니다.

예외: 실제 예배방 종료 / 만료
- 예배방은 기존과 같이 생성 후 12시간 동안 열립니다.
- 방이 종료·만료된 경우에는 입력창을 없애지 않고 비활성화하며 이유를 안내합니다.
- 음향석 로그인 만료·방 삭제·잘못된 개인 복귀코드에는 기존 접근 제한을 유지합니다.

업로드
1. 기존 운영 데이터가 있으면 관리자 데이터·백업에서 SQLite 백업을 내려받으세요.
2. ZIP을 풀어 내부 파일·폴더 전부를 기존 app.py와 같은 위치에 업로드하세요.
3. Streamlit Reboot 후 기존 열린 브라우저 탭을 한 번 새로고침하세요.
4. 버전 2026.09.21-r48을 확인하세요. Secrets와 기존 데이터는 삭제하지 마세요.

현장 확인 순서
키즈룸 요청 → 음향석 답변 → 조치 완료·보관 → 키즈룸 확인 →
키즈룸 대화 입력창에 추가 메시지 → 음향석 진행 대화에 재등장 → 다시 답변.
처리 완료는 예배방 종료가 아니므로 대화를 계속할 수 있어야 합니다.

검증 범위
- 로컬 SQLite 자동 테스트로 대화 상태별 입력창, 권한, 중복 방지, 오류 후 재전송을 검사합니다.
- 독립 브라우저 2개와 모의 실시간 알림으로 키즈룸↔음향석 반복 대화를 검사합니다.
- 운영 Supabase 정책/트리거·교회 네트워크와 실제 iPhone Safari는 배포 후 확인이 필요합니다.
- r47의 실시간 수신과 자동 보완 확인 기능은 유지합니다.
- 신규 DB 컬럼이나 유료 서비스는 추가하지 않았습니다. 운영 DB를 직접 변경하지 않았습니다.
- 행사·매뉴얼·운영 기록의 영구 저장소 이전은 여전히 보류입니다.
