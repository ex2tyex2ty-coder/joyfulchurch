r47 · 양방향 실시간 대화 / 자동 복구

변경 사항
1. 싱어 요청과 음향석 답변·처리 상태를 대화 영역에 자동 반영합니다.
   기존 사람별 대화와 큰 무음 팝업을 유지합니다. 상대방이 화면을 실제로 읽었다고
   추정하지 않습니다. ‘저장 완료’와 음향석이 누른 ‘확인·처리 중’은 다른 상태입니다.
2. 실시간 알림(Broadcast)이 기본입니다. 정상 연결 중에도 약 21초마다 변경 여부를
   대조해 놓친 알림을 보완합니다. 대화 본문 전체는 변경 시에만 다시 읽습니다.
3. 실시간 연결 장애/설정 누락 시 약 3초 간격으로 자동 확인합니다.
   네트워크·DB 처리 시간은 별도이며 3초 이내 전달을 보장하는 것은 아닙니다.
   DB 접속까지 실패하면 기존 기록에 경고를 표시하고, 재시도는 최대 30초 간격으로 늦춥니다.
4. 재연결을 6회 후 포기하던 동작을 수정했습니다. 간격을 최대 30초로 제한하면서
   자동 복구합니다. 인증 만료 후 화면 복귀 때도 다시 인증을 확인합니다.
5. ‘실시간 수신 정상 / 자동 확인으로 연결 중 / 연결 끊김’을 구분하고
   마지막 데이터 확인 시각을 표시합니다. DB 조회 성공만으로 실시간 정상이라 하지 않습니다.
6. 대화 갱신이 참여자 입력창을 재실행하지 않습니다. 음향석 답변 초안도 유지합니다.
   전송 성공은 DB 저장 확인 후에만 표시하며 실패·결과 불명 시 내용과 재전송 버튼을 보관합니다.
   같은 전송을 재시도할 때 식별자를 재사용해 중복 저장을 방지합니다.
   실패 내용은 현재 브라우저 세션에서만 보관하며 완전 새로고침 후에는 사라질 수 있습니다.
7. 화면이 숨겨지면 수신을 쉬고 화면 복귀/네트워크 복구 시 놓친 대화를 확인합니다.
   방 종료·접속 권한 만료 시 자동 확인을 중단합니다. 잠금 화면 푸시는 아닙니다.

업로드
- 기존 행사·매뉴얼·운영 기록이 있다면 먼저 관리자 ‘데이터·백업’에서
  SQLite 복구용 백업을 생성하고 본인 컴퓨터로 다운로드하세요.
- ZIP을 풀어 내부 파일·폴더를 기존 app.py 위치에 업로드하고 Streamlit Reboot.
- audio_sync.py와 sound_realtime 폴더도 반드시 함께 업로드하세요.
- 기존 Secrets, 데이터, Google 원본을 삭제하지 마세요.
- 버전 표시가 2026.09.18-r47인지 확인하세요. 기존 켜둔 탭은 한 번 새로고침하세요.

설정과 비용
- 새 유료 서비스·요금제 변경·운영 DB 이전이나 삭제는 실행하지 않았습니다.
- 기존 AUDIO_DATABASE_URL, AUDIO_ENGINEER_PIN을 사용합니다.
- 즉시 수신에는 AUDIO_SUPABASE_URL, AUDIO_SUPABASE_PUBLISHABLE_KEY 및 기존
  Supabase 익명 인증/비공개 실시간 채널 설정이 정상이어야 합니다.
- 실시간 설정이 잘못되어도 DB 접근이 되면 자동 확인으로 동작합니다.
- 자동 확인으로 DB 조회량이 증가합니다. 연결된 기기 수에 따라 사용량을 점검하세요.
- 이번 기능을 위한 신규 DB 테이블이나 컬럼 추가는 없습니다.
  기존 버전과 동일한 초기 설정/실시간 정책 설치 코드는 앱 실행 시 그대로 동작합니다.

검증 및 현장 리허설
- 로컬 SQLite와 모의 Supabase 인증/Broadcast로 다중 브라우저 검증합니다.
  운영 Supabase의 실제 트리거·정책·네트워크 지연이나 iPhone Safari 검증을 대체하지 않습니다.
- 배포 후 휴대폰 2대와 음향석 PC에서 요청 → 처리 중 → 답변 → 확인을 테스트하세요.
- 새로고침 없이 양방향 표시되는지, 다른 참여자의 대화가 보이지 않는지 확인하세요.
- Wi-Fi 끊기/복구, 휴대폰 잠금 후 복귀, 긴 시간 켜둔 후 재요청을 테스트하세요.
- 자동 확인 문구만 계속 보이면 실시간 설정을 확인해야 합니다. 비밀번호/Secrets는 공유하지 마세요.

별도 미완료 사항
- 행사·매뉴얼·운영 기록의 영구 저장소 이전은 여전히 보류입니다.
- 주보는 실제 원본이 없어 미등록 안내 상태입니다.
